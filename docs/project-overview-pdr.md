# Kiwamero Tracking: 要件定義書 (draft)

対象: `kiwamero-tracking/`。親ディレクトリの旧 `kiwamero-tracker` アプリとは別製品として扱う。
根拠: ユーザーとのヒアリング、`docs/research/tracker-sites-analysis.md`、`plans/261027-1834-kiwamero-tracking/plan.md`。
状態: プロダクト方針と本番の Workers + D1 は合意済み。実装方式と診断ロジックは未検証。

## 1. 目的

公開されている VALORANT 戦績を、tracker.gg の VALORANT 領域全体に
極力近い視覚言語・情報構造で表示する。
閲覧にログインを要求せず、Kiwamero 独自の診断・監視・共有・開発者機能を統合する。
名称は **Kiwamero Tracking**。公開予定ドメインは `tracking.kiwamero.dev` (Cloudflare)。

## 2. 確定した要件

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| R-01 | tracker.gg の VALORANT 領域全体を参考にする | ホーム、検索、プロフィール全タブ、ランキング等の実在する画面とナビを調査し、デスクトップを先に同一条件のスクリーンショットで比較し、その後モバイルを確認する。サイト名・ロゴは独自とする |
| R-02 | 公開プロフィールの検索と閲覧はログイン不要 | 初回は PC の Riot ID (`name#tag`) を検索し、取得可能なプレイヤーの戦績に直接アクセスできる。非公開・未収録は取得不可と明示する。Console は対応データを調査後に検討 |
| R-03 | 英語/日本語切り替え | 初期表示はブラウザの言語設定 (`Accept-Language`) に合わせる。手動変更後の再読み込みでも選択が維持され、主要なナビ・統計・エラー表示が翻訳される |
| R-04 | 戦績データはライブ取得 | HenrikDev API 等、利用条件を満たすソースから取得し、更新時刻・データ取得元を明示する |
| R-05 | プロフィールの概要と詳細 | ランク/RR、勝率、K/D、ACS、ADR、HS%、試合一覧・展開詳細、エージェント/マップ/シーズン別統計を表示する |
| R-06 | フィルタとページング | モード、Act、エージェント、マップで絞り込み。データがある範囲を明示して追加読み込みできる |
| R-07 | 監視対象リストと通知 | Discord OAuth ログイン済みユーザーだけが自分のリストを追加・削除・閲覧できる。ユーザーごとの Discord Webhook へ登録直後の直近1試合を通知し、その後は1時間ごとに新しい試合を確認して重複なく通知する。監視対象はシステム全体でまず100プレイヤーまで |
| R-08 | スマーフ診断・アカウント査定 | 既存サイトの観測可能な診断項目・判定傾向を調査し、公開データから独自の参考スコアを算出する。計算式・対象試合数・不確実性を表示し、人を断定しない |
| R-09 | 戦績カード共有 | 初回は公開プロフィールの最新統計をその都度表示する共有 URL を用意する。スナップショット保存・PNGダウンロード/画像生成は初回対象外 |
| R-10 | 自分専用の開発者 API | 環境変数に設定した Discord ID 許可リストの所有者だけが利用・キー管理できる。認可・レート制限・仕様書を備え、一般ユーザーへ公開しない |
| R-11 | Cloudflare Workers + D1 公開 | `tracking.kiwamero.dev` の Worker 配信、D1、秘密情報、監視・ログを検証してから公開する |
| R-12 | 高度な統計とプレイヤー比較 | 取得可能なデータでパーセンタイル、ランク推移、比較指標を独自に計算する。比較母集団と期間を明示し、算出できない項目は表示しない |

初回リリースの対象は R-01〜R-12 全て。段階的に作るが独自機能も初回完成条件。
LFG、OBS オーバーレイ、クロスヘア/ラインナップなどの同等機能は調査・後続段階の候補。

## 3. ページと権限

| ページ/機能 | 匿名 | Discord ログイン |
| --- | --- | --- |
| ホーム・Riot ID 検索 | 可 | 可 |
| プロフィール概要/試合/分析/エージェント/マップ/診断 | 可 | 可 |
| 戦績カード閲覧/共有 URL | 可 | 可 |
| 監視リスト管理 | 不可 | 自分のリストのみ |
| 開発者ドキュメント | 可 | 可 |
| 開発者 API・キーの発行/失効 | 不可 | サイト所有者のみ。一般の Discord ユーザーは不可 |

既存プロトタイプの経路: `/`, `/login`, `/watchlist`, `/developers`,
`/valorant/profile/riot/{encodedName%23tag}/{tab}` (`overview`, `matches`,
`performance`, `agents`, `maps`, `diagnosis`, `share`)。
正式な URL 仕様はルーティング検証後に固定する。`#` は URL 内では `%23` とする。
ランキングなど tracker.gg の VALORANT 側で実際に存在するページは
現状の試作にまだなく、次フェーズでページ/機能一覧を調査してルートを確定する。
他ゲーム向け機能は対象外。
有料・ログイン限定の機能は、利用可能な公開データと自前ロジックで
**同等の体験を独自実装**する方針。元サイトの制限を回避してデータを取得しない。
データが足りず実現できない機能は代替案/未対応理由を表示する。

## 4. データ・可用性の制約

- ユーザー希望は「全プレイヤーをログイン不要で見たい」。公開取得可能な範囲では全員を対象とし、
  非公開設定・Riot/取得元 API の制限・未収録試合は回避しない。
- 取得不能なプレイヤーは **404 / 非公開 / API 障害 / レート制限** を区別して表示する。
  別人のシードデータを要求された Riot ID に差し替えて表示しない。
- シードの Meiy データは UI 開発/テスト専用。通常の本番検索結果として使わない。
- API 応答の形式と許可範囲を確認し、欠損値・モード別の差・集計母数を明示する。
- 秘密の HenrikDev キーはサーバー側のみに置く。ブラウザへ渡さない。
- 監視は Workers Cron で1時間ごと、システム全体で100プレイヤーを上限に開始。
  同一プレイヤーを複数ユーザーが監視する場合は照会を共用し、各ユーザーの
  Webhook には別々に配信する。API予算と同一試合の重複排除を設計する。
- Discord Webhook URL は秘密情報として扱い、D1への安全な保存方法を選定。
  登録時に Discord Webhook 以外の URL を受け付けず、ログ・画面・公開 API に露出させない。
- 初回登録後は直近1試合をそのユーザーの Webhook に通知する。
  外部送信の実行前には送信先と通知内容を確認する。

## 5. 非機能・品質ゲート

- デスクトップとモバイルの主要ページで崩れず、キーボード操作・コントラストを確認。
- ローディング、データ未取得、エラー、レート制限、匿名/ログイン済みを別々に検証。
- Cron 再実行・429・Webhook 配信失敗時も同じ試合の重複通知や失敗の見落としを防ぐ。
- `.env`/DB/認証秘密情報を Git に入れない。API キーは平文で再表示しない。
- `npm run lint`、`npm run build`、API/認証のテスト、実ブラウザ動作確認を完了条件とする。
- 画像・デザインは比較参照として扱う。tracker.gg の商標・ロゴ・文章・有料機能を
  自社のものとして表示しない。Riot/データ提供元の利用条件を公開前に確認する。

## 6. 確定/未決

確定: サイト名、独立した新規アプリ、ブラウザ言語初期値と日英切り替え、公開可能な範囲の匿名閲覧、
非公開データは取得不可表示、Discord OAuth、初回機能全部入り、所有者専用 API
(Discord ID 許可リスト)、観測可能な既存診断項目から参考スコアと根拠を表示、
初回のカードは常に最新の URL 共有、1時間ごとの新規試合監視と Discord Webhook
通知、Cloudflare Workers + D1 とサブドメイン、VALORANT の PC 優先。
tracker.gg の有料/ログイン限定機能は高度な統計・比較を最優先して独自開発する。

未決: Workers 向け Next.js/ORM/認証の具体的な互換構成、
HenrikDev キー/Discord OAuth 資格情報、API 契約と利用規約、
診断の算出式・誤判定の表現、所有者 Discord ID の設定、
サイト全体の実ページ目録と各ページのデータ取得可能性。
技術候補と移行条件は `docs/system-architecture.md` に記録する。
